- 全変更を `feature/frontend-setup` ブランチに commit & push

### 学んだポイント

**フロントエンド（React + Vite）:**
- `npm create vite@latest frontend -- --template react-ts` で雛形を作成
- `npm run dev` で開発サーバーが `http://localhost:5173` で起動
- `tsx` は `ts-node` の代替で TypeScript 7.x に対応している

**バックエンド（Express + TypeScript）:**
- `npm init -y` → `npm install express` → `npx tsc --init` の順で初期化
- `tsconfig.json` の `rootDir` は Prisma 7 のファイル配置と競合するので削除
- `tsx src/index.ts` でサーバーを起動できる

**Docker + PostgreSQL:**
- `docker-compose.yml` に `services`, `volumes` を定義する
- `docker compose up -d` でバックグラウンド起動
- `docker compose ps` でコンテナの状態を確認
- `-d` は detach（バックグラウンド実行）の意味

**Prisma 7:**
- `npx prisma init` で `prisma/schema.prisma`, `prisma.config.ts`, `.env` が生成される
- Prisma 7 では `schema.prisma` に `url` を書かず、`prisma.config.ts` で管理する
- `env("DATABASE_URL")` の接続文字列は `backend/.env` に書く
- `npx prisma migrate dev --name init` でマイグレーションファイル作成 + DB反映

**npm と npx の違い:**
- `npm install` = パッケージをインストールして `node_modules` に保存
- `npx` = インストール済みのパッケージを実行する

- Express のルーティングが URL と HTTPメソッドで処理を振り分ける仕組みを学んだ

### 学んだポイント

**Express のルーティング:**
- `app.use('/exercises', exercisesRouter)` で入口から処理本体へ渡す
- `router.get('/')` や `router.delete('/:id')` でメソッドごとに分岐する
- サーバー再起動しないと新しいルートが有効にならない

**Prisma のスキーマ変更手順:**
1. `schema.prisma` を編集
2. `npx prisma migrate dev --name 変更名` でDBへ反映
3. `npx prisma generate` で TypeScript の型を更新
4. VS Code で `Developer: Reload Window` して波線を消す

**req の使い分け:**
- `req.params.id` → URL の `:id` 部分（例: `/exercises/1` の `1`）
- `req.body` → POST/PATCH で送られてきた JSON の中身
- `req.query` → URL の `?sort=asc` のようなパラメータ

**論理削除の設計:**
- `deletedAt DateTime?` を追加して、日時が入ったら「削除済み」
- 一覧取得では `where: { deletedAt: null }` で未削除だけ返す
- DB から消えないので履歴を保持できる
