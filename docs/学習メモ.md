### 学んだポイント

**Git の基本概念:**
- Git は「変更履歴の管理」ツール
- Commit = 「この時点でのファイル状態を記録」する操作
- ブランチ = 「独立した作業環境」で、main に影響を与えない
- .gitignore で秘密情報（.env, node_modules など）を除外

**ブランチ運用の安全性:**
- main ブランチは常に動作する本番コード
- feature/〇〇 で開発 → GitHub に push → Pull Request でレビュー → OK なら main に merge
- このフロー により、バグが main に混入する危険を防ぐ

**GitHub ワークフロー（実務）:**
1. feature ブランチで作業・commit
2. ローカルで動作確認
3. GitHub に push
4. Pull Request を作成（変更内容を説明）
5. コードレビュー（他人が確認）
6. OK なら merge して main に反映
7. main は常に安全 ✅

**覚えた重要コマンド:**
- `git init` - リポジトリを初期化
- `git add .` - 変更をステージング
- `git commit -m "メッセージ"` - 履歴を確定
- `git branch -M main` - ブランチ名を統一
- `git switch -c feature/〇〇` - 新しいブランチを作成
- `git push -u origin main` - ローカルの履歴を GitHub に送信
- `git log --oneline --decorate --graph --all` - 履歴をグラフ表示

**Conventional Commits（メッセージ規約）:**
- `chore:` - 機能でない変更（設定、ドキュメント）
- `feat:` - 新機能を追加
- `fix:` - バグを修正
- `docs:` - ドキュメントを更新
- `refactor:` - コードを改善
